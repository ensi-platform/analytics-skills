# Подготовка QA-документов

Общие правила — в [AGENTS.md](../../../AGENTS.md), приём задачи, проектирование проверок и представление комплекта — в [инструкции QA](../../agents/qa.md).

## Вход и результат

- Основания: `01-BRD.md`, `02-ADR.md` и `03-FR.md` из `features/<slug>/analytical documents/`.
- При переработке прочитай весь текущий QA-комплект; при разделении старого формата — исходный `04-TEST-CASES.md`.
- Получи явный выбор пользователя: тест-кейсы или чек-листы. Если выбор отсутствует, не начинай подготовку и запроси его по разделу 8 `AGENTS.md`.
- Сохраняй четыре документа выбранного комплекта в `features/<slug>/testing documents/` по соответствующим шаблонам:

| Категория | Тест-кейсы | Чек-листы |
|---|---|---|
| Функциональные | [Functional TC](templates/Functional%20TC.md) | [Functional CL](templates/Functional%20CL.md) |
| Интеграционные | [Integration TC](templates/Integration%20TC.md) | [Integration CL](templates/Integration%20CL.md) |
| API | [API TC](templates/API%20TC.md) | [API CL](templates/API%20CL.md) |
| Матрица | [Matrix](templates/Matrix.md) | [Matrix](templates/Matrix.md) |

## Подготовка

1. Заполни три документа выбранного типа по инструкции QA и соответствующим шаблонам. Группируй проверки по модулям, взаимодействиям и API-категориям. Для чек-листов каждый пункт формулируй как конкретный проверяемый результат.
2. После подготовки трёх документов собери Matrix по их фактическим проверкам без ожидания согласования. Для каждого FR и решения ADR перечисли полные ID связанных тест-кейсов или чек-листов выбранного типа, сгруппированные по категориям; укажи конкретные пробелы и блокировки. Ссылайся на фактические файлы и версии выбранного комплекта. Учитывай каждый тест-кейс или чек-лист один раз, не подсчитывай отдельные флажки как отдельные чек-листы. Общие ограничения опиши один раз перед таблицами.
3. Сверь комплект: ID проверок и вопросов, блокировки, локальные и общие количества, приоритеты, ссылки и версии документов должны совпадать. Условия и данные должны быть доступны из каждого документа с проверками.

### Общие условия и тестовые данные

Описывай подготовку кратко и простыми словами: оставляй только данные, роли, связи, настройки и действия по восстановлению, необходимые для проверок конкретного документа. Используй понятные названия; если без условных обозначений не обойтись, расшифруй их в небольшой таблице рядом с данными. Не повторяй условия и оговорки без необходимости; детали отдельной проверки оставляй рядом с ней. Каждый документ с проверками должен содержать достаточно сведений для самостоятельного выполнения.

Изменения и перенос из объединённого документа выполняй по разделу «Изменения и разделение существующего документа» инструкции QA.
