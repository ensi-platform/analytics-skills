# Подготовка QA-документов

Общие правила — в [AGENTS.md](../../../AGENTS.md), приём задачи, проектирование проверок и представление комплекта — в [инструкции QA](../../agents/qa.md).

## Вход и результат

- Основания: `01-BRD.md`, `02-ADR.md` и `03-FR.md` из `features/<slug>/analytical documents/`.
- При переработке прочитай весь текущий QA-комплект; при разделении старого формата — исходный `04-TEST-CASES.md`.
- Результаты сохраняй в `features/<slug>/testing documents/` по четырём шаблонам:

| Документ | Шаблон |
|---|---|
| `Functional TC.md` | [Functional TC](templates/Functional%20TC.md) |
| `Integration TC.md` | [Integration TC](templates/Integration%20TC.md) |
| `API TC.md` | [API TC](templates/API%20TC.md) |
| `Matrix.md` | [Matrix](templates/Matrix.md) |

## Подготовка

1. Заполни кейсы по правилам разделов «Анализ и проектирование» и «Формат и качество» инструкции QA; поля таблиц заданы в шаблонах. Группируй проверки по модулям, взаимодействиям и API-категориям.
2. Собери Matrix по фактическим кейсам всех трёх документов. Состав матриц, обозначения связей и сводки определены в её шаблоне.
3. Сверь комплект: ID кейсов и вопросов, блокировки, локальные и общие количества, приоритеты, ссылки и версии документов должны совпадать. Условия и данные должны быть доступны из каждого документа с кейсами.

Изменения и перенос из объединённого документа выполняй по разделу «Изменения и разделение существующего документа» инструкции QA.
