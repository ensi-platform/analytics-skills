# Test Cases Document

## Фича: Авторизация по номеру телефона с одноразовым SMS-кодом

**Проект:** Ensi Platform — сайт продажи собственной продукции.

**Ответственный QA:** QA-агент; ФИО ответственного за выполнение требует уточнения.

**Дата:** 09.11.2026

**Версия:** 1.0

**Статус:** На согласовании

**Тестовое окружение:** требует уточнения (Q-QA-01); разрешённый изолированный стенд со стабом SMS и управляемым серверным временем, не production.

**API-документация:** [FR, раздел 3](03-FR.md#3-api-спецификация); URL фактической OpenAPI/Swagger-документации требует уточнения (Q-QA-01).

**Основание:** Документ разработан на основе [BRD](01-BRD.md), [ADR](02-ADR.md) и [FR](03-FR.md) (BRD v1.0, ADR v1.0, FR v1.0). Статусы и взаимные версии оснований проверены: все три согласованы.

Документ содержит проект проверок, а не результаты тестирования. Кейсы не выполнялись; реальные SMS не отправлялись. Отметка `×` в матрице означает запланированную проверку конкретного пункта, не факт успешного выполнения и не гарантию полного покрытия всех его деталей.

### Общая подготовка и тестовые данные

- **Q-QA-01 — общий допуск к исполнению:** до выполнения нужны адрес/сборка стенда, разрешённые тестовые номера, доступ к данным и журналам только чтения, способ подготовки фикстур/барьеров/сбоев и управления временем, контракт CSRF для положительных запросов и утверждённая очистка. Пока они не предоставлены, выполнение всего набора не готово; это отдельно от семи специальных блокировок ниже.
- **A и B** — два разных российских мобильных номера, выделенных для SMS-песочницы. Значения нужно получить по Q-QA-01; произвольные реальные номера не использовать. **N_UNSUPPORTED** — согласованные фикстуры иностранного/немобильного/нероссийского номера +7 с подтверждённой классификацией; адресата реальных SMS не создавать.
- **B1–B4** — независимые cookie-контексты тестового браузера; **A_ID** — фактический integer клиента A из фикстуры. **C/C_A=012345**, **C_B=654321** — данные управляемого SMS-стаба/фикстуры, а не требование выдавать фиксированный код в реализации. Для случайного генератора код считывается только разрешённым тестовым способом из SMS-песочницы; не из production-логов.
- **T0=2026-11-09T12:00:00Z** — условный серверный момент для каждой независимой фикстуры. Временные границы проверяются управляемым временем непосредственно в момент серверного решения; ожидание реальной доставки не заменяет точную проверку. Каждая независимая ветвь начинается с исходной фикстуры, чтобы успешный ввод не потребил код для следующей ветви.
- **K1/K2…** — различные непредсказуемые ключи `Idempotency-Key`; **token_A/token_old/token_used** — реальные токены созданных тестовых попыток соответствующего состояния, не литералы из примеров FR. **cookie_A** — секретная cookie только тестового клиента; не помещать её значение в отчёт.
- **H_JSON** = `Content-Type: application/json`, `Accept: application/json`, корректная CSRF-защита выбранного стенда для положительных изменяющих запросов. Строка `body={"phone": A}` в таблице — компактная параметризованная запись: перед запросом A подставляется как JSON-строка. Записи Cookie и заголовков — не часть JSON body. Base URL не придумывается.
- Если специально не сказано иное: A/B не заблокированы, окна лимитов чисты, для новой отправки новый ключ, шлюз-стаб доступен, B1 — гость. Перед проверкой истечения/блокировки готовят именно указанное состояние; лимиты нельзя обходить реальными массовыми отправками.
- После каждого кейса сохранить обезличенные доказательства и очистить только его тестовые записи/сессии/ключи через согласованный механизм Q-QA-01, очистить cookie-контексты и вернуть серверное время/инъекции сбоев. Не редактировать основания и production-данные.
- Пометка **«Заблокирован: Q-QA-…»** означает, что конкретный механизм/ожидаемая деталь ещё не определены, хотя смысл проверки известен. Остальные кейсы спроектированы и ожидают общей подготовки стенда; их выполнение также не объявлено состоявшимся.

## 2. Интеграционные тест-кейсы

**Системы:** витрина, Customer Auth (Passport), его PostgreSQL, Communication, его PostgreSQL-журнал, SMS-шлюз/управляемый стаб.

**Протокол:** HTTPS между сервисами и шлюзом; SQL для своих хранилищ. Конкретные внутренние URL, webhook-подпись, реквизиты и API поставщика требуют уточнения, не изобретаются.

**Описание:** проверить корреляцию одной отправки, достоверность и порядок статусов, атомарность кодов/аккаунтов/сессий, сохранность лимитов при сбоях и отсутствие секретов.
