# Business Requirements Document (BRD)

## Фича: Кнопка прокрутки наверх страницы

**Дата:** 16.11.2026
**Версия:** 3.0
**Статус:** Согласован

**Источники:** запрос и уточнения пользователя от 16.11.2026, включая приложенное изображение с перечнем браузеров и устройств; [карта проекта](../../../PROJECT-MAP.md), версия 1.1.

## 1. Контекст и цель

Покупатели просматривают длинный каталог товаров на сайте. При просмотре может потребоваться вернуться в начало страницы.

**Бизнес-цель:** упростить покупателю возвращение к началу страницы при просмотре длинного каталога.

**Критерии успеха:**

- Кнопка появляется при достижении второго экрана каталога (`scrollY >= innerHeight`) и скрывается, если прокрутка меньше текущей высоты видимой области. Состояние обновляется при изменении размера окна без дополнительной прокрутки.
- Кнопка расположена в правой верхней части экрана поверх других кнопок, пока она активна; точные отступы не заданы. После нажатия страница плавно прокручивается к началу за 300–500 мс независимо от расстояния, если не включено уменьшение анимации.
- При включённом уменьшении анимации переход выполняется мгновенно, необязательные анимации отключаются. В пределах страницы каталога плавная прокрутка не прерывается взаимодействиями пользователя; повторное нажатие до её завершения ничего не меняет. При уходе со страницы каталога прокрутка прекращается без задержки навигации и влияния на положение новой страницы.
- Кнопка соответствует WCAG 2.2 AA, доступна с клавиатуры и экранным дикторам и имеет видимый индикатор фокуса.
- Если кнопка скрывается, когда на ней находится фокус, фокус переносится на кнопку «Главная страница». Доступное название кнопки прокрутки — `scroll button`, видимая текстовая надпись не нужна.

Количественные бизнес-метрики и способ их измерения не заданы.

## 2. Проблема

При просмотре длинного каталога покупателю может быть неудобно вручную возвращаться к началу страницы. Текущее поведение сайта и наличие похожего элемента не проверялись.

## 3. Бизнес-требования

| ID | Требование |
|---|---|
| BR-01 | Покупателю должна быть доступна кнопка возврата наверх только в каталоге товаров. |
| BR-02 | Кнопка должна появляться, когда величина вертикальной прокрутки страницы больше или равна текущей высоте видимой области браузера (`scrollY >= innerHeight`). |
| BR-03 | По нажатию кнопки страница должна плавно возвращаться в начало. |
| BR-04 | Кнопка должна скрываться, когда величина вертикальной прокрутки становится меньше текущей высоты видимой области (`scrollY < innerHeight`). |
| BR-05 | При изменении размера окна порог должен пересчитываться, а состояние кнопки — обновляться без дополнительной прокрутки. |
| BR-06 | Активная кнопка должна располагаться в правой верхней части экрана поверх других кнопок; точные отступы не заданы. |
| BR-07 | Плавная прокрутка должна занимать 300–500 мс независимо от расстояния и не прерываться взаимодействиями пользователя в пределах страницы каталога. Повторное нажатие до завершения прокрутки не должно менять её ход. При уходе со страницы каталога активная прокрутка должна прекращаться, не задерживая навигацию и не изменяя положение прокрутки новой страницы. |
| BR-08 | При `prefers-reduced-motion: reduce` переход к началу должен выполняться мгновенно, а необязательные анимации должны быть отключены. |
| BR-09 | Кнопка должна соответствовать WCAG 2.2 AA, поддерживать управление клавиатурой и экранные дикторы и иметь видимый индикатор фокуса. |
| BR-10 | Если кнопка прокрутки скрывается, когда на ней находится фокус, фокус должен переходить на кнопку «Главная страница». |
| BR-11 | Доступное название кнопки для экранного диктора — `scroll button`; видимая текстовая надпись не требуется. |
| BR-12 | При повторном открытии каталога состояние кнопки определяется текущей позицией прокрутки с учётом механизма восстановления позиции. |

## 4. User Story

| ID | Роль | Действие | Ожидаемый результат |
|---|---|---|---|
| US-01 | Покупатель | Как покупатель, просматривающий длинный каталог, я хочу нажать кнопку возврата наверх | Чтобы плавно вернуться к началу страницы без ручной прокрутки. |

## 5. Риски

| Риск | Вероятность | Влияние | Митигация |
|---|---|---|---|
| Порог достижения второго экрана будет реализован непоследовательно на разных устройствах. | Требует уточнения. | Кнопка появится не в ожидаемый момент. | Проверить равенство порогу и обновление состояния при изменении размера окна по BR-02, BR-04–05. |
| Плавная прокрутка может быть неудобна пользователям с ограничениями восприятия движения. | Требует уточнения. | Не все покупатели смогут комфортно пользоваться кнопкой. | Выполнить требования WCAG 2.2 AA и учитывать настройку уменьшения анимации по BR-08–09. |

### Остаётся проверить

- Конкретные маршруты каталога и соответствие используемой прокрутки `scrollY` и `innerHeight`.
- Наличие и доступность кнопки «Главная страница» на страницах каталога как цели переноса фокуса.
- Соответствие доступного названия `scroll button` требованию WCAG 2.2 AA.

Вопрос ADR v2.0 об уходе из каталога закрыт ответом пользователя 16.11.2026: активная прокрутка прекращается при уходе со страницы; повторное открытие учитывает восстановленную позицию. Ответ внесён в BR-07 и BR-12 текущей версии BRD.
